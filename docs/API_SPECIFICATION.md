# API Specification: BrisJS Website

> **Runtime:** none today (static client-side SPA) → target: Strapi (Node.js) REST/GraphQL
> **Audience:** the BrisJS frontend is the only consumer
> **Spec:** Strapi auto-generates its REST/GraphQL schema once content types exist
> **Last updated:** 2026-06-11

The current site **exposes no API of its own**. It is a static client that **consumes** several
external sources at runtime. This document records those consumed contracts (the de-facto API
surface today) and reserves space for the **target Strapi API**, to be filled in as content
types are decided in [`features/001-strapi-content-modeling`](../features/001-strapi-content-modeling/).

## Consumed External Sources (current)

Configured in [`config.json`](../config.json) and fetched in [`app.js`](../app.js).

### Talks — Google Sheet (TSV export)

`GET https://docs.google.com/spreadsheets/d/<id>/export?format=tsv&...`

Tab-separated rows (header row skipped), parsed by [`lib/tsvTalks.js`](../lib/tsvTalks.js).
Column order:

| Col | Field | Notes |
| --- | ----- | ----- |
| 0 | `id` | talk id (used in `#talk-<id>` routing) |
| 1 | `date` | epoch milliseconds |
| 2 | `title` | talk title |
| 3 | `speakers` | comma-separated speaker names |
| 4 | `twitters` | comma-separated Twitter handles (positionally aligned with speakers) |
| 5 | `youtube` | YouTube watch URL (`?v=<id>` extracted) |
| 6 | `slides` | slides URL |
| 7 | `code` | code/repo URL |
| 8 | `synopsis` | free-text description |

### Events — Meetup API (JSONP)

`GET https://api.meetup.com/brisjs/events?...&sig_id=<id>&sig=<signature>`

Fetched via `fetch-jsonp`. Only the latest event (`data[0]`) is used; fields read include the
event name, `time`, venue, and description (bound into `[data-latest]` elements). The `sig`
signature is opaque and pre-baked into the URL — see HLD Open Questions.

### Jobs & Talk Requests — GitHub Issues API

`GET https://api.github.com/repos/brisjs/meetups/issues?state=open`

Issues are fetched once, rendered through `markdown-it`, then filtered **client-side by label**:

| Label | Rendered into |
| ----- | ------------- |
| `Jobs / Employment` | `#template-jobs` |
| `Talk Requests` | `#template-talksrequested` |

Fields used: `title`, `body` (markdown → `html`), `labels[].name`, `updated_at`.

### Speaker profiles — committed cache

[`data/twitter.json`](../data/twitter.json), regenerated by `tools/build-twitter` (Twitter API
v1, deprecated). Keyed by Twitter handle; each entry provides `username`, `name`,
`description`, profile image, and website `url`.

### Organizers — committed JSON

[`data/contact.json`](../data/contact.json): array of `{ name, role, bio, twitter, email, photo }`.

### Conventions (intended)

- Request/response bodies are `application/json`
- Timestamps use ISO 8601: `YYYY-MM-DDThh:mm:ssZ`
- Strapi default REST shape: `{ data, meta }` with entries carrying `id` + `attributes`
